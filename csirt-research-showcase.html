The Three Concrete Design Interventions

Rather than an arbitrary aesthetic reskin, the Laravel 12 artifact executed three targeted engineering interventions designed to eliminate baseline failure modes.

INTERVENTION 01

Contrast Tokens & Palette

Replaced arbitrary bright orange with a strict CSS token system (--navy: #003580, --ink: #0A0F1A, --mist: #F4F5F7). Total elimination of the intrusive modal pop-up.

Evaluator Rating: 4.04 ± 0.71 / 5.0
Favorable: 85.2% (23/27 respondents)
INTERVENTION 02

Guided Incident Flow & Tickets

Komdigi-style single-page form (/bug-hunter/laporan/baru) with Terms & Conditions gate, parameter binding preventing database crashes, and INS-YYYY-XXXX ticket tracking.

Form Workflow Rating: 3.96 ± 0.76 / 5.0
DB Crashes: 0 reported during walkthroughs
INTERVENTION 03

Inclusive Accessibility Widget

Fixed accessibility widget featuring Web Speech API text-to-speech (id-ID), 4-level font gauge, contrast modes (Dark, High, Invert), dyslexia-friendly fonts, and persistent state.

Widget Usefulness: 3.96 ± 0.85 / 5.0
Favorable: 81.5% (22/27 respondents)

Hotspot 1: Brand Color Palette & Contrast Tokens

WCAG SC 1.4.3 · Level AA

Legacy Defect: The legacy portal utilized jarring bright orange (#FF6B00) backgrounds and links that failed WCAG 1.4.3 on 8 out of 8 pages.
New Implementation: Refactored using design tokens: --navy: #003580 and --ink: #0A0F1A in public/css/style.css, achieving zero contrast violations across the entire site.
User Validation: 85.2% of survey evaluators rated the new palette favorable (Mean: 4.04/5).

The 3-Snapshot Refinement Cycle (DSRM Proof)

Snapshot A (Commit e631baf): Eliminated 100% of Level A violations (alt text, link names, button names). Remaining AA contrast failures were isolated to hardcoded footer hex codes.
Snapshot B (Commit e64a57d): Token refactor introduced --muted-on-dark and --faint-on-dark. Resulted in 0 axe contrast nodes.
Snapshot C (Commit 8cd5e99): Multi-tool payoff! WAVE caught borderline AA contrast on the dark-header eyebrow (~3.5:1) that axe skipped. Fixed via token swap to achieve complete multi-tool clearance.

Audit Note: Why Do WAVE Alerts Still Appear?

WAVE reports 7–17 yellow "Alerts" on the redesign. Human review confirms these are non-violating heuristics: 5 orphaned label alerts originate from the accessibility widget's button controls (where labels describe button actions rather than text inputs), and small text alerts flag 10.5px date tags which fully pass contrast. None constitute WCAG Level A or AA failures.

The Mathematical Straight-Lining Phenomenon:
Five respondents in the new survey (18.5%: N12, N16, N17, N19, N26) selected identical uniform ratings across all 10 alternating items (e.g., all 4s or all 5s). Due to alternating positive/negative polarity, any uniform vector mathematically defaults to exactly 50.0: [5(k - 1) + 5(5 - k)] × 2.5 = 20 × 2.5 = 50.0. Excluding this psychometric artifact reveals the true clean SUS of 75.11 ± 11.27.

Academic Honesty Limitations & Gaps

What Still Needs Work? (Critical Limitations)

A rigorous academic study must not only celebrate triumphs. The evaluation revealed genuine design tensions and technical limitations to address in future DSR cycles.

1. The Civic Reporting Dilemma: Mandatory Login Barrier

Access Barrier

While the guided form eliminated database crashes and issued tickets, requiring users to create a "Bug Hunter" account and log in (/bug-hunter/login) introduced severe procedural friction. White-hat researchers and citizens expect anonymous submission with tokenized email tracking.

Evaluator Quotes:
"Untuk lapor insiden harus login dulu. Apakah tidak bisa menggunakan anonim? Lalu tiket dikirim ke email..." — Respondent N20
"Sebaiknya tidak perlu login. Untuk tracking status bisa dibuat seperti tracking paket kurir." — Respondent N22
➔ Next DSR Iteration: Decouple incident submission from auth; issue courier-style public token lookups.

2. Evaluator Cohort: Absence of Clinical PwD Testing

Method Gap

Evaluators were professional cybersecurity and administrative personnel from BSSA Diskominfotik (100% domain sample), not certified persons with disabilities (PwDs) using screen readers (NVDA/JAWS).

Empirical Boundary: Zero Level A/AA automated errors proves syntax compliance, but does not substitute for clinical screen-reader task completion studies with visually impaired citizens.
➔ Next DSR Iteration: Conduct moderated usability trials with blind and low-vision user cohorts.

3. Mobile Viewport Nav Clutter Below 1200px

Responsive Polish

The desktop navbar contains 4 partner logos, CSIRT mark, 5 main links, search, and auth buttons (~1230px min-content). On viewports below 1200px, partner logos are forcibly hidden via CSS, and mobile hamburger navigation needs polish.

Evaluator Quote: "Perlu penambahan menu hamburger responsif pada tampilan ponsel kecil agar menu tidak terpotong." — Respondent N26
➔ Next DSR Iteration: Implement dedicated mobile off-canvas drawer navigation.

4. Ticket Tracking Menu Discoverability

Navigation IA

Although tickets (INS-YYYY-XXXX) are issued and viewable on /bug-hunter, several evaluators struggled to find where past reports were stored after navigating back to the public homepage.

Evaluator Quote: "Saya juga tidak menemukan menu untuk tracking tiketnya dari halaman utama." — Respondent N22
➔ Next DSR Iteration: Place prominent "Lacak Tiket Insiden" input directly in the public navbar and homepage hero.
